01 / OVERVIEW

总览（Overview）

agent-hub 是一套跨主机 Coding Agent 统一调度与多轮会话编排系统。它让人类工程师、外部聊天机器人（Bot）或某台开发机上的主控 Agent，能够以统一协议向多台内网或异地受管节点（如 macmini、mbp、Linux 与 Windows 主机）安全派发、续聊、实时观测和强杀无头本地 Coding Agent（支持 agy、pi、omp、codex、claude）。同时支持纯调用端 Bot 通过专属引导模板 /dl/client-bootstrap.md 隔离接入。

目标节点无需开放任何公网入站端口。受管节点上的守护进程通过一条主动向云端（示例域名 ahub.bobocai.win，可通过 AHUB_URL 覆盖）发起的出站 WebSocket 长连接完成注册、目录与能力上报和唤醒接收；所有存在并发竞争或数据完整性要求的操作（认领任务锁、续租心跳、回传最多 900KB 产物、级联取消）均走强一致性的 HTTP + D1 CAS 事务。此外，当开发者在节点本机直接交互运行 agy、pi、omp、codex、claude 或 grok 时，宿主 Hook 可调用 ahub native-emit 将「需要人工确认（interaction_needed）」与「回合总结（turn_summary）」经云端脱敏去重后异步推送至节点绑定的默认外部 Bot（如 Grok Bot）。

三级认证解析链与权限 Scope

authenticateRequest（apps/hub-worker/src/auth.ts）按严格顺序完成单次边界认证：刻意将 Bearer 置于浏览器 Cookie 之前，防止残留的过期 Cookie 阻塞机器 Token 调用；同时对单域名 SPA 的 Cookie 鉴权强制执行同源 CSRF 守卫。

PRIORITY 01
Cloudflare Access Header
读取请求头 Cf-Access-Jwt-Assertion，使用远端拉取并缓存的 JWKS 公钥验证 RS256 签名，直接映射为 admin 主体（access_jwt）。
PRIORITY 02
Bearer / WS 子协议 / 引导密钥
解析 Authorization: Bearer 或 WebSocket Sec-WebSocket-Protocol: bearer, <token>；先常量时间比对 BOOTSTRAP_ADMIN_TOKEN_SHA256，再查 api_keys 确认未吊销。
PRIORITY 03
同源 Access Cookie（防 CSRF）
提取 CF_Authorization Cookie；强校验 Origin 匹配且 Sec-Fetch-Site 为 same-origin / none，阻断跨站 WS 劫持。
  • admin Scope：全量管控权限，可签发/吊销任意密钥、绑定节点默认通知通道 default_notify_key_id、调整节点 draining 或并发度、强制重排队列及调用租约回收端点。
  • node Scope：必须绑定单一 bound_node_id，仅限接入 /ws/node、调用本节点的 /claim、/heartbeat、/approval、/complete，以及上报本节点的 POST /api/v1/nodes/:id/native-events；节点 ID 由后端从 Token 权威读取，禁止客户端自报或跨节点代报。
  • client Scope：面向外部 Bot 与低权限委派，在 REST 与 /ws/stream（强制要求携带 ?run_id=<id> 单任务订阅）上统一强制执行 bound_node_id ∩ allowed_nodes_json 节点交集校验与创建者（created_by_key_id）所有权隔离，受 allow_unsandboxed 沙箱豁免与 max_depth_limit 深度上限约束，自动剥离节点 default_notify_* 元数据，并可绑定独立 AES-256-GCM 加密的 Bot Webhook（notify_webhook_ciphertext）。

3.1 节点接入、能力探测与 macOS TCC 常驻壳

节点启动最易踩的两个坑是「外置盘休眠或 macOS TCC 弹窗拖死建连」与「二进制热更新导致 Full Disk Access 授权失效」。守护端为此做了两层结构性设计：

  • 非阻塞首帧握手与渐进热刷新：守护进程（internal/daemon/daemon.go）启动后调用 scanWorkspacesBounded 扫描 project_roots 下 1~2 层项目目录（同名目录自动升格为 <parent>/<name> 消歧键，见 internal/daemon/workspaces.go），但硬性限时最多等待 5s。超时即携带缓存或空切片建连 /ws/node 发送首帧 node.hello（catalog_status: "pending"）。云端 NodeHub DO（apps/hub-worker/src/node-hub.ts）将 {role, nodeId, keyId, connNonce} 序列化到 WebSocket Hibernation Attachment（唤醒后免重查鉴权），调用 upsertNodeHello（apps/hub-worker/src/db.ts）更新 nodes 表（刻意保留既有 draining 状态不被重连冲掉），回推 hub.welcome 并扇出 node.status。与此同时，internal/daemon/capabilities.go 在后台以单探测 4s 超时、10m 缓存 TTL 异步采集五类 Agent 模型目录（执行 agy models、omp models --json、pi --list-models，读取 ~/.codex/config.toml + models_cache.json 与 ~/.claude/settings.json），目录或慢速扫描完成后在同一连接补发 node.hello 热刷新。
  • macOS 冻结 CDHash 与 SIGHUP -> exit(42) 无损热升级：macOS launchd 若直接运行频繁自更新的 ~/.local/bin/ahub，每次替换都会变更签名哈希使外置盘 TCC 授权失效。internal/service/darwin_app.go 在 ~/Applications/AhubDaemon.app 生成一次性 ad-hoc 签名并冻结 CDHash 的宿主壳，由 launchd 拉起壳内的 ahub node shim（internal/service/shim_unix.go），再由 shim 监管真正的 ~/.local/bin/ahub node serve。当执行 ahub update（internal/selfupdate/update.go）校验 SHA-256 并同目录原子替换后，internal/service/service.go 优先读取 ~/.config/ahub/node.pid（internal/daemon/pidfile.go）发送 SIGHUP（internal/daemon/signal_unix.go）：node serve 将本地内存 d.draining 置为 true 停止认领新单（不改写云端持久 draining），等待在途子任务全部报完 CompleteRun 后以退出码 42（ExitReload）退出，node shim 在 200ms 内重拉新版二进制，既不断在途任务又保留 TCC 权限。若未命中 PID 文件且检测到 AHUB_RUN_ID != ""（说明更新命令跑在远程子任务内部），函数直接返回 "skipped_inside_run"，严禁调用 launchctl kickstart -k 自杀父守护进程。

3.2 任务提交五道门禁

调用方提交 POST /api/v1/runs（apps/hub-worker/src/index.ts）时，先经 apps/hub-worker/src/validation.ts 的 rejectUnknownKeys 执行严格单次边界校验，再进入 createRun（apps/hub-worker/src/db.ts）顺序通过五道门禁：

  1. 沙箱与节点范围校验：当 sandbox: false 时，client Key 必须启用 allowUnsandboxed；目标节点必须同时命中 bound_node_id 与 allowedNodes 交集且状态非 draining（处于排水态则返回 409 NODE_DRAINING，CLI 映射为可重试退出码 75）。
  2. 会话亲和与四级工作区消歧：若传入 thread_id，强制继承原会话绑定的 (node_id, workdir)；若为新建会话，resolveWorkspace 按「精确绝对路径 -> 节点列表为空时的绝对路径兜底 -> 精确 key -> 路径后缀或目录名」四级解析 workdir。多项目同名时返回 400 WORKDIR_AMBIGUOUS 并在 details.candidates 中列出全部候选供上游 Agent 一步修正。
  3. 幂等去重：携带 Idempotency-Key 时，命中同参数历史任务直接返回原记录，参数冲突则返回 409 IDEMPOTENCY_CONFLICT。
  4. 不对称血统传递与递归防环：守护端向子 Agent 进程注入 AHUB_RUN_ID、AHUB_THREAD_ID、AHUB_ROOT_RUN_ID、AHUB_DEPTH 四个变量（internal/runner/env.go），但子进程内调用 ahub run 时，internal/cli/cli.go 只读取 AHUB_RUN_ID 作为 parent_run_id，其余血统全由云端从父记录权威计算：depth = parent.depth + 1 <= min(parent.max_depth, client.maxDepthLimit)（默认 max_depth = 1，超限返回 409 DEPTH_LIMIT_EXCEEDED），彻底杜绝客户端伪造深度；而 AHUB_DEPTH 仅供子 Agent 在执行前按 SKILL.md 自检收敛。随后云端执行 SQLite WITH RECURSIVE ancestors 回溯整条祖先链，一旦发现任意祖先已占用同一 (targetNodeId, resolvedWorkdir)，立即返回 409 DELEGATION_CYCLE_DETECTED（CLI 对深度超限与环路统一退出 78 阻止盲目重试）。
  5. 原子落库与即时唤醒：db.batch 原子写入 threads 与 runs（status = 'queued'，priority_order = max + 100），随即通知 NodeHub DO 向目标节点下发轻量 hub.wake 帧。

3.3 「WS 轻量唤醒 + HTTP CAS 认领 + 双通道续租 + HTTP 结单」混合调度闭环

为何不直接通过 WebSocket 派发任务和回传结果？因为 Cloudflare Durable Object Hibernation 既存在单帧体积制约，也不适合承载需要跨多行一致性的并发锁。agent-hub 将通道职责清晰切分：

  • 三处认领触发点：守护端在 ① 握手收到 hub.welcome 后（清扫离线期间积压队列）、② 收到实时 hub.wake 帧后、③ 任意本地任务退出释放目录锁的 defer 中，均会调起 claimAndSpawn 请求 POST /api/v1/nodes/:id/claim。
  • 三重守卫 CAS 锁：claimRunsForNode（apps/hub-worker/src/db.ts）按 priority_order ASC, created_at ASC 拉取候选，跳过守护端传来的本地 busy_workdirs，在单条 SQL UPDATE 条件中同时校验：① status = 'queued'；② NOT EXISTS 同 (node_id, workdir) 下存在 claimed | running | needs_approval 活跃任务；③ 当前节点活跃数 < max_concurrency 且节点非 draining。中标后写入 lease_owner = "<nodeId>:<connNonce>" 与 90s 租约 lease_expires_at，并将所属 Thread 当前的 native_session_id 快照进该 Run。
  • 双通道续租与闪断容忍：守护端每 25s 发送 WS 层 Ping 与业务帧 node.ping（触发 renewNodePingLeases 批量顺延活跃任务租约），同时每个运行中任务的独立协程每 30s 调用 HTTP POST /api/v1/runs/:id/heartbeat（heartbeatRun 校验 lease_owner，若任务已被取消或判败则返回 should_abort: true 兜底强杀）。本地子进程派生自守护根上下文 serveCtx 而非单次 WS 连接上下文 sessionCtx；云端 WS 断线时仅将无剩余连接的节点标为 offline，不立刻标败在途任务，留出 90s 宽限期让守护端无缝重连续租。
  • 过程态、审批检查点与终态通道隔离：WS run.state 帧在 applyRunStateFrame 中仅接受 running 与 needs_approval（传入终态枚举直接忽略返回 null）；流式事件 run.event / run.events 经 INSERT OR IGNORE 幂等写表并实时转发。当本地 agy 输出 NEEDS_HUMAN_APPROVAL 并退出子进程后，守护端先调 POST /api/v1/runs/:id/approval 持久化摘要、产物预览、native_session_id 与远控链接，并在总运行预算内继续持锁心跳驻留（超时则调用 /complete 上报 APPROVAL_TIMEOUT），直到人类通过 POST /api/v1/runs/:id/resolve（ahub resolve 或 Web「标记已放行」）结单并由云端下发 hub.abort 释放互斥锁。所有终态（done / failed / cancelled）均由强一致 REST 事务写入 runs（其中 completeRun 校验 lease_owner，对 output_md 执行 UTF-8 字符边界安全的 900KB 截断），回填 native_session_id 至 threads 表，重算 active_runs_count，入队通知并唤醒内存等待者。
  • 失联租约回收（绝不自动重入队列）：每分钟 Cron 执行 reapExpiredLeases（apps/hub-worker/src/db.ts）扫描超时的 claimed / running / needs_approval 任务并统一置为 failed（NODE_LEASE_EXPIRED）。一旦审批驻留协程所在节点崩溃断租，needs_approval 也会被有限期回收，彻底杜绝目录互斥锁永久死锁；由于本地 Agent 可能已修改代码文件，严禁自动退回 queued 重复执行。

codex exec --json -m <m> -c model_reasoning_effort=...（Prompt 走 stdin 传 -） exec resume --json ... <id> - Prompt 始终经标准输入传入避免 Shell 截断；注意 resume 子命令分支不重复附加 -s 沙箱标志。
claude -p --output-format json, 非沙箱加 --dangerously-skip-permissions, --model, --effort <e> --session-id <id> 支持四档 effort（low / medium / high / max，省略 auto/off，尊重配置覆盖），解析最终 result 对象与 session_id。
  • 最小环境白名单与委派凭据：BuildSanitizedEnv（internal/runner/env.go）先剥离宿主环境中的节点 ahub_nod_* 凭据与其他未列明密钥，仅放行基础变量（PATH、HOME、SSH_AUTH_SOCK、CODEX_HOME、XDG_* 等）及 4 项血统追踪变量；仅当节点配置了低权限 client 级 delegation_token 时，才向子进程注入 AHUB_TOKEN 与 AHUB_URL。
  • 手动 os.Pipe() + 2s 排空（根治快速退出截断）：Go 标准库 cmd.StdoutPipe() 会在 cmd.Wait() 返回瞬间关闭读端——当短命子进程吐出超过 64KB NDJSON 并立即退出时，读取协程极易丢失尾部关键的 agent_end 正文。internal/runner/adapters.go 改用手动 os.Pipe() 搭配单行上限 2MB 的 ReadLinesBounded（internal/runner/stream_reader.go）：父进程起完子进程即关闭自身写端，cmd.Wait() 返回后最多等待 2s 让读协程自然消费至 EOF，若遇后台逃逸孙进程占住写端则到期强制关闭读端防挂死。
  • 流式白名单过滤与 EventBatcher：adapters.go 静默丢弃 token 级增量事件（仅在内存 streamedAssistantText 拼装以备中途取消时抢救半截回复，并用 sawStructuredEvent 防止取消回退原始 NDJSON 污染产物），将工具调用精简至 512 字符内、剥离 turn_end 巨大载荷。随后 internal/daemon/batcher.go 为每个 Run 维护单调 seq：approval_needed 或积压满 100 条时 0ms 立即发；status 采用「250ms 窗口前沿立即刷出、窗口内突发留在缓冲随下一拍合并」；其余按 250ms 周期打包成 run.events 批量上报。
  • 独立进程组两阶段强杀：Unix 下 internal/runner/procgroup_unix.go 以 Setpgid: true 隔离每次运行，超时或收到 hub.abort 时向 -pgid 发 SIGTERM 轮询等待 5s，未退则补发 SIGKILL 彻底灭绝子孙进程树（Windows 下通过 taskkill /T /F 执行）。

3.5 调用端两阶段等待、退出码契约、多 Bot 隔离通知与 Web 单调同步

调用端与控制面共同保护上游 Agent 的有限上下文窗口和同步等待超时边界：

  • 两阶段无缝等待与指令脱敏边界：ahub run --wait <dur> 先将阶段一等待夹逼在 [0, 45000ms]（避开 Cloudflare 100s 网关 524 超时），请求 POST /api/v1/runs?wait_ms=...。NodeHub DO 注册内存 Waiter 后立即二次查库防超快任务竞态；若指定了 --notify grok|webhook 且首段未完结，CLI 将 webhook_armed 置为 true 并立即返回退出码 0 交由云端异步回调；若未配通知且仍有剩余等待预算（例如 --wait 10m），则无缝切入阶段二 waitViaStream 订阅 /ws/stream?run_id=...，收到任一停止态（done/failed/cancelled/needs_approval）均执行限时长 5s 的 GET /api/v1/runs/:id?tail_bytes=16384 补全摘要与尾部 16 KiB 预览；若阶段二遇到 401/403/404 或持久传输错误，立即如实透传退出码（78/64/75）而非伪报超时 24。序列化输出前显式清空 LeaseOwner，并对 Prompt 执行对称凭据脱敏与默认 1536 字节截断（--full 保留完整脱敏文本与 $VAR 占位；全系统仅节点 POST /api/v1/nodes/:id/claim 返回原始明文 prompt；Grok Bot 按 client-bootstrap.md 在派单瞬间直接展示脱敏指令）。
  • 多 Bot 三路通知矩阵（Fail-Closed）：任务入队 ahub-outbound-notify 队列前，enqueueRunNotificationIfNeeded（apps/hub-worker/src/db.ts）在任务终态与首次进入 needs_approval 时按三条路由规则分流：① 当 client Key 显式传 --notify 时强制锁定 route_mode = "key"，仅使用该 Key 自身的 AES-256-GCM 加密 Webhook；② 当人工或 admin 发起根任务（depth === 0 且 notify.target === "none"）时，若目标节点绑定了有效的 default_notify_key_id 则自动升级为 route_mode = "node_default"（严禁 client 静默任务与 depth >= 1 子任务落入 node_default，防止跨 Bot 串信与通知风暴）；③ 人工或 admin 显式传 --notify 且节点未绑定默认通道时，才退回全局环境变量 global_legacy。消费端 apps/hub-worker/src/notify-queue.ts 同时处理带脱敏 prompt_preview（上限 1200 字符）的 ahub_run_completed 与节点原生事件 ahub_native_event（固定标记 action_required: "notify_user_only"）；若绑定 Key 已吊销、权限变更或解密失败，严格 Fail-Closed 直接写 failed 并 ack()，绝不回退全局 Webhook；外部 HTTP 异常按指数退避（2s、4s、8s、16s）重试，第 5 次仍失败则落盘 WEBHOOK_DELIVERY_FAILED 并显式 ack()。
  • Web 三栏工作台、多轮补水与单调状态合并：apps/web/src/App.tsx 协调左栏会话/节点（FleetThreadsPane.tsx）、中栏对话与四级能力联动派发台（ConversationPane.tsx + capabilities.ts）及右栏实时检视甲板（InspectorPane.tsx：事件流、1s 租约倒计时、同节点队列拖拽重排 POST /api/v1/runs/reorder、root_run_id 血统树、级联取消，以及仅对 admin 开放的节点 default_notify_key_id 默认通道绑定与「通道失效/已吊销」实时徽标）。中栏使用代次化水合集合对不超过 128KB 的完成任务自动拉取 view=full（超过 4000 字符或 60 行自动折叠并支持展开，超过 128KB 展示显式截断提示）；外壳与表单控件统一约束 position: relative 与 overflow: hidden 防止视口溢出。为解决 REST 补水与 /ws/stream 并发乱序，apps/web/src/stores/task-store.ts 的 mergeRunRecord 实施单调合并法则：终态不可被非终态覆盖，比较 updated_at 时间戳及状态秩（queued:0 < claimed:1 < running|needs_approval:2 < terminal:3），并将每任务实时事件环形裁剪在 500 条上限内。
CLI 退出码 Go 常量（exitcodes.go） 触发条件与语义 上游 Agent 建议动作
0 ExitOK 任务 done、--notify 异步武装成功，或查询/列表/取消操作成功。 直接消费 summary / output_preview，按需补调 ahub result --full。
10 ExitRunFailed 任务已到达 failed（含租约过期）或 cancelled 终态。 读取 error_code 与尾部日志排查根因，勿盲目在原目录并发重跑。
20 ExitNeedsApproval 任务进入 needs_approval 等待人类交互授权。 提取 remote_control_url 转发人类审批，批准后可由 ahub resolve 或 Web「标记已放行」收口。

64 ExitBadUsageOrInput 参数非法、工作区路径未知/重名歧义（WORKDIR_AMBIGUOUS）、资源不存在或幂等冲突。 修正参数或根据 details.candidates 消歧后重新提交。

3.6 节点端本地原生会话主动推送（ahub native-emit 与双向防环）

当开发者在节点本机终端或 IDE 直接交互运行本地 Agent（不受控于云端 Run）时，节点侧主动推送消息走一条完全脱离 NodeHub DO 与 /ws/stream 的纯异步旁路：

图 C · 本地原生会话主动推送与双向防环旁路（不经 NodeHub DO） NATIVE-EMIT + D1 + QUEUE
  • 双通道硬分界与双向防环：ahub node serve 拉起受控子进程时经 BuildSanitizedEnv 注入 AHUB_RUN_ID 与 AHUB_DEPTH（根任务为 "0"）。一旦受控任务内部触发宿主全局挂载的 Hook，runNativeEmit（internal/cli/native_emit.go）在读取 node.json 与 stdin 之前即返回 inside_ahub_run 并以退出码 0 静默退出；反向出站载荷强制附带 action_required: "notify_user_only"，配合 Routine 规范第 6、7 条禁令切断递归派单死循环。
  • 六类宿主适配、先验目录门禁与流式大文件解析：claude（parseClaudeHookEvent）与 grok（parseGrokHookEvent，兼容 snake_case 与 camelCase）过滤 stop_hook_active 与 idle_prompt，映射 Notification 为 interaction_needed、Stop 为 turn_summary；codex 读取末尾位置参数或 stdin 的 agent-turn-complete；pi 与 omp 通过共享扩展 ahub-native-notify.ts 过滤子代理与无头 -p 会话后以 detached: true 拉起 CLI；claude、grok、agy 均在打开 transcriptPath 前先调用 isWorkdirAllowedForNativeNotify（优先 allowed_roots，为空回退 project_roots，两者皆空或目录为空则 Fail-Closed 拦截）；agy 以 64 KiB 缓冲、4 MiB 单行上限流式扫尾，忽略 USER_CANCELED、fullyIdle == false 与 exit_plan_mode，并将末步 ask_question 自动升级为 interaction_needed 提取编号问题清单。
  • 确定性幂等键、凭据硬隔离与全链路三次脱敏：deterministicEventID 按 <prefix>_<sha256[:20]> 生成幂等键（优先组合 promptId、不超过 32 MiB 的 Transcript 行数 lines:<N>、executionNum 或 step:<S>:lines:<N>，缺少锚点时退回 15s 时间桶 tb:<unix/15>）。ahub native-emit 彻底绕过 ResolveCredentials，仅读取命令行标志或 node.json 中的 hub_url 与 ahub_nod_* 令牌，不依赖本机 ahub node serve 守护进程存活。标题（<= 200）与摘要（<= 4000）分别在「Node 出网前（redact.Text）」、「Worker 入库前（redactSecrets）」与「Queue 出站前（redactSecrets）」完成三次对称脱敏。
  • 云端三态分流与投递期换绑 Fail-Closed：控制面校验 scope === "node" 且 boundNodeId === nodeId，先按 UNIQUE(node_id, event_id) 幂等去重（重复上报返回 200 OK { deduplicated: true } 不再入队），再按节点默认通道状态写入 D1：未绑定记 skipped（200），绑定 Key 已吊销/无 Webhook/移除节点权限记 failed（200），有效则写入 queued 并入队（202 Accepted）。消费端 resolveNodeDefaultWebhook 额外核验当前 nodes.default_notify_key_id 是否仍等于入库快照 e.notify_key_id，若排队期间节点换绑了其他 Bot，同样按 Fail-Closed 终止投递，绝不跨 Bot 串台。

05 / GOTCHAS & SAFEGUARDS

关键隐性机制与工程防线（Gotchas & Safeguards）

以下 8 项曾是代码实现与契约之间的典型隐性差异与边界风险，现已通过状态持久化、权限交集收敛、错误透传及跨平台守护防线逐项闭合；二次开发或排障时仍需关注各自生效边界：

#01 进程退出型 needs_approval 的持久化驻留、人工放行与租约回收

当 agy -p 输出单对象 NEEDS_HUMAN_APPROVAL 并立即退出子进程时，internal/daemon/daemon.go 会先调用 POST /api/v1/runs/:id/approval 将 summary、output_md、native_session_id 与 remote_control_url 原子落盘并唤醒等待方，随后在 TimeoutSec 预算内驻留心跳以接收放行或取消指令。人类在远端批准后，可通过 ahub resolve <run_id> 或 Web 控制台「标记已放行」（POST /api/v1/runs/:id/resolve）将任务收口为 done；同时 D1 迁移 0003_needs_approval_lease_index.sql（idx_runs_active_lease）与 apps/hub-worker/src/db.ts 中的 reapExpiredLeases 均已将 needs_approval 纳入互斥锁保护与租约过期超时回收，节点离线后仍会按 APPROVAL_TIMEOUT 语义释放目录互斥锁。

#02 claude 思考强度（effort）目录上报与全链路透传

internal/daemon/capabilities.go 为 claude 适配器上报 efforts: ["low", "medium", "high", "max"] 后，Go 执行端 internal/runner/adapters.go（BuildCommandSpec）、Web 派发台命令预览 apps/web/src/lib/utils.ts（buildRunCliPreview）与 docs/04-ahub-cli-and-node-daemon.md 均已同步透传 --effort 参数；仅当调用方通过 extra_args 显式覆盖 --effort 时跳过自动注入，避免重复传参冲突。

#03 client 密钥双字段交集校权与 patchQueuedRun 改派防线

apps/hub-worker/src/auth.ts、db.ts 与 index.ts（含 /ws/stream）对 client 密钥统一采用 bound_node_id 与 allowed_nodes 的交集权限校验，且 patchThread 与 forkThread 均验证 client_key_id 所属权。对 queued 态 Run 调用 PATCH /api/v1/runs/:id 改派 node_id 或 workdir 时，控制面强制复验节点可达性、I-2 同线程工作区亲和及 I-3 委派环路防线，并同步刷新单 Run 线程的 threads 锚点。

#04 默认 --wait 45s 阶段切换、Stage-2 错误透传与配置文件清单

ahub run 的默认 --wait 为 45s，恰好等于首段 HTTP wait_ms 的硬上限 45000ms；若服务端跑满 45s 返回 202，剩余预算 remaining <= 0 仍会退出 24，长等任务需显式传入更大超时（如 --wait 10m）或接续执行 ahub wait <run_id>。一旦进入 Stage-2 /ws/stream，传输或协议错误会按真实错误传播而非误报为 ExitWaitTimeout（24）；当状态进入 needs_approval 时，CLI 会带有限超时拉取一次摘要补全 output_preview 后退出 20。此外，internal/config/config.go 实际仅读写 credentials 与 node.json 两个文件，无历史文档提及的 config.json。

#05 Windows 平台服务托管、ahub-shim.exe 与 node.reload 哨兵重载

除 windows/amd64 静态交叉编译、taskkill /T /F 进程树强杀（internal/runner/procgroup_windows.go）与 .old 重命名自更新外，internal/service 已补齐 Windows 任务计划程序（schtasks 注册 AhubNodeDaemon）、ahub-node-runner.cmd 与 ahub-shim.exe 服务包装；internal/daemon/reload_sentinel.go 通过 node.reload 哨兵文件配合 tasklist CSV 进程镜像校验触发平滑排空退出 42，由外部守护包装拉起新版二进制（仅 macOS 特有的 AhubDaemon.app TCC 权限冻结机制在 Windows 下不适用）。

#06 native_events 纯出站旁路属性、软吊销外键保留与入库顺序边界

native_events 不经过 NodeHub DO、不向 /ws/stream 广播实时帧，也不暴露 GET /api/v1/native-events 读接口。调用 DELETE /api/v1/keys/:id 执行的是更新 revoked_at 的软删除而非物理 DELETE，因此 nodes.default_notify_key_id 不会被外键 ON DELETE SET NULL 清空，使 default_notify_valid 明确翻转为 false 并将后续事件精确记为 failed（DEFAULT_CHANNEL_INVALID_OR_REVOKED）而非静默 skipped。同时注意：createNativeEvent 先执行 INSERT OR IGNORE 写入 notify_status = 'queued' 再调 env.NOTIFY_QUEUE.send（若 send 瞬时失败且同 event_id 重试，幂等命中将返回 deduplicated: true 而不会补偿入队）；Queue 消费端在第 5 次投递失败时写入 WEBHOOK_DELIVERY_FAILED 并显式调用 message.ack()，仅未捕获异常才进入 ahub-outbound-notify-dlq。

#07 ahub native-emit 与 ahub node serve 凭据解析差异及先验目录门禁

ahub native-emit（internal/cli/native_emit.go）刻意绕过 config.ResolveCredentials，仅读取命令行 --token 或 node.json 中的 ahub_nod_* 令牌，防止交互终端内的 client/admin 凭据触发 403 FORBIDDEN_SCOPE；而 ahub node serve（internal/cli/cli.go）仍优先调用 ResolveCredentials（读取 --token、AHUB_TOKEN、credentials），为空时才回退 node.json，二者解析顺序不同。此外，claude、grok 与 agy 适配器均在打开磁盘 transcriptPath 之前先调用 isWorkdirAllowedForNativeNotify，阻断白名单外目录的阻塞管道（FIFO）或文件越权读取。

#08 控制面全链路 prompt 对称脱敏与 target="none" 跨 Bot 隔离门禁

internal/redact/redact.go 与 apps/hub-worker/src/redact.ts 构成对称 12 类凭据脱敏防线（保留 $VAR 与 <PLACEHOLDER>）：全系统仅受管节点调用 POST /api/v1/nodes/:id/claim 时获取原始明文 prompt，所有 REST 列表/详情、/ws/stream 快照、CLI --json、以及 ahub_run_completed（上限 1200 字符）与 ahub_native_event Webhook 载荷均返回脱敏视图。同时，enqueueRunNotificationIfNeeded 规定未传 --notify（target = "none"）时自动走节点默认通道 node_default 严格限定于 depth === 0 且发起方为人工或 admin 的根任务，彻底拦截 client 密钥静默任务跨 Bot 串信。
